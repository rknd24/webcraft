# スプリント1　振り返り
- ER図を作成する重要性を学んだ
- これを書くことで複数のテーブルの関係性を視覚的に見ることができるようになる。
- ER図において重要なのは、2つのテーブルがどういう関係なのかを言語化できること。双方向に対して、共通の動詞を考え、一方が相手に対して、どの程度あるのかを考える。
- GitHubのMermaidを使えばGitで差分や履歴が残せGithub上で図として表示できる。
- テーブルを分ける時の判断方法として、目印となるものは同じものが複数出て良い（例えばidなど）が、データとなるもの（例えばtag_name）などが複数出てくると、テーブルを分ける時の基準となる。
- 躓いたこととして、選択肢のテーブルを1行に詰めて作ってしまい、本来の拡張性を考え、いつでも選択肢を増やせるという目的を見失ってしまっていた。次からは上記のテーブル分けの考えを参考にして考える。
- 当初はバックエンドの最小版を27日までに作る予定だったが、他社の選考の兼ね合いでER図の作成までにとどまった。
- 次にやることとして、テーブル定義から行う。

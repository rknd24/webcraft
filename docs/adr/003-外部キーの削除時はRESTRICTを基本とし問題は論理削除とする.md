# 003-外部キーの削除時はRESTRICTを基本とし問題は論理削除とする

## 状況
外部キーはあるテーブルからあるテーブルに向かって何かを参照した時に使われたカラムを表す。外部キーを削除した際に、それに付随している関係のあるものをどうやって処理するかを考える必要があった。

## 決定
連鎖を防ぐため、外部キーの根元であるcategoryはRESTRICTにし、categoryの削除で全データが消えないようにした。
またquestionはRESTRICTと論理削除を用いた。
またselected_option_idに関してもRESTRICTで対応した。
ほかの外部キーはCASCADEで、外部キーを削除した時点でそれに付随しているカラムも削除する設計にした

## 理由とあきらめたこと
RESTRICTを用いた外部キーの共通認識として、連鎖してしまうのを防ぐため、そして残したいものを考えたときにこのRESTRICTを用いた。RESTRICTを用いることで、参照先のデータを消そうと思っても消えることがなくなるのである。
あきらめたこととして、この削除の工程をプログラムとして手順が必要になったのと、論理削除を実装したことで、生きている問題をとるのに、条件が増えた

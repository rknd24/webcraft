# WebCraft 仕様書（たたき台）

## 目的
Web技術の基礎を、自分で問題を作る・4択で解く・間違えたところを復習する、の繰り返しで身につける。
このプロダクトの目的は「作る過程でWeb技術と知識を学ぶこと」で、完成後に使い続けることは目的にしない。

## 出題の考え方
- 知識が定着するのは作問する時なので、自分で問題（問題文・選択肢・正解・解説・出典）を作り、4択で出題する
- 割り切り：解く時は問題文から答えを思い出せてしまい、理解の確認としては弱い
- AIによる出題・採点は作らない。その分の時間をDB設計・認証・トランザクションに使う
- 判断の経緯は `docs/adr/001-4択形式にする.md`

## 最初の範囲（カテゴリ）
- HTTP・ネットワーク
- ブラウザとフロント
- API・バックエンド
- DB
- 認証・セキュリティ

カテゴリはデータとして持ち、後から追加できるようにする（OS・インフラなどは後で）。

## MVP（スプリント1〜2）
- 問題を登録できる（問題文・選択肢4つ・正解・解説・出典URL・カテゴリ）
- カテゴリを選ぶと、その中から問題が1問出る
- 4択で答えると、正誤と解説・出典が見られ、結果を記録できる

## やらないこと（今は）
- ログイン・ユーザー管理（スプリント3で追加）
- 間違えた問題の自動出し直し（スプリント4で追加）
- AIによる出題・採点、記述式（ADR 001で見送り）

## ユーザーストーリー
- 学習者として、カテゴリを選んで問題を解きたい。苦手な分野を集中して学びたいから
- 学習者として、解答後に解説と出典を見たい。根拠を確かめて理解したいから
- 問題を作る人として、問題に出典URLを紐づけたい。間違った知識を覚えないようにしたいから

## データモデル（自分で書く）
次の問いに答えながら、テーブルとカラムを書く。
- 問題・選択肢・カテゴリ・解答履歴は、それぞれ何テーブルに分ける？
- 選択肢は問題と同じテーブルに持つ？別テーブルにする？正解はどう表す？それぞれの良し悪しは？
- 解答履歴に何を残せば、後で「苦手な問題の出し直し」に使える？

## 将来の方向性（今は作らない）
- 企業の研修向け：社内資料から問題を作って登録し、理解度を管理者が確認できる
- 採用の技術テスト向け：問題で理解度を測り、受けた側にもフィードバックを返す
- そのため、テーブル設計は「どの組織のデータか」を後から足せる形にしておく
